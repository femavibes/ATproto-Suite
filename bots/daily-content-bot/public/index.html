Seasonal Tags Explained

Seasonal tags allow you to boost the probability of certain content appearing during specific time periods.

What are Seasonal Tags?

Seasonal tags don't have to be actual seasons like "winter" or "summer". They can be any custom period you want to emphasize, such as:

  • Holidays (christmas, halloween, new_year)
  • Events (conference_season, back_to_school)
  • Campaigns (awareness_month, fundraising)
  • Or any custom period you define

How the Weighting Works

During active periods, content gets boosted based on how many matching seasonal tags it has:

  • No seasonal tags: 1x weight (normal probability)
  • 1 matching tag: 3x weight (3x more likely to be selected)
  • 2 matching tags: 4x weight (4x more likely to be selected)
  • 3+ matching tags: 5x weight (5x more likely to be selected, capped)

Note: Non-seasonal content can still be posted during active periods, but seasonal content will appear more frequently.

Cloud Backup Setup Guide

Set up automatic cloud backups to Google Cloud Storage with versioning, retention policies, and restore functionality.

Features

  • Scheduled Backups: Automatic backups on configurable schedule
  • Versioning: Timestamped backup files for easy identification
  • Retention Policy: Automatic cleanup of old backups
  • Restore Functionality: One-click restore from any backup
  • Manual Backups: Create backups on-demand

Setup Instructions

1. Create Google Cloud Storage Bucket

  1. Go to Google Cloud Console
  2. Create a new project or select existing one
  3. Enable the Cloud Storage API
  4. Create a storage bucket:
    • Choose a unique bucket name (e.g., my-bot-backups-12345)
    • Select appropriate region
    • Choose "Standard" storage class
    • Set access control to "Uniform"

2. Create Service Account

  1. Go to IAM & Admin > Service Accounts
  2. Click "Create Service Account"
  3. Give it a name (e.g., bot-backup-service)
  4. Grant it the "Storage Object Admin" role
  5. Create and download the JSON key file
  6. Save the key file securely on your server (e.g., /home/user/gcs-key.json)

3. Configure Bot Settings

Fill in the settings below:

  • Google Cloud Project ID: Your GCP project ID
  • Service Account Key File Path: Full path to your JSON key file
  • Storage Bucket Name: Your bucket name
  • Backup Schedule: Choose frequency (daily recommended)
  • Retention Days: How long to keep backups (30 days recommended)
  • Enable Cloud Backup: Check this box to activate

4. Test the Setup

  1. Click "Create Backup Now" below
  2. Check that the backup appears in the backup list
  3. Verify the backup file exists in your GCS bucket

Backup Contents

Each backup ZIP file contains:

  • quotes.json - All quotes
  • words.json - All words
  • used_quotes.json - Usage history for quotes
  • used_words.json - Usage history for words
  • weighting_settings.json - Current weighting configuration

Security Notes

  • Keep your service account key file secure and readable only by the bot process
  • Use least-privilege access (Storage Object Admin role only)
  • Consider using IAM roles instead of key files if running on Google Cloud
  • Regularly rotate service account keys

Cost Considerations

Google Cloud Storage costs are minimal for bot backups:

  • Standard storage: ~$0.02/GB/month
  • Typical bot backup: <1MB
  • Monthly cost: <$0.01

Set appropriate retention days to control storage costs.

Troubleshooting

  • "Cloud backup not configured": Check that all three settings (Project ID, Key File, Bucket Name) are filled in correctly.
  • "Failed to initialize Google Cloud Storage": Verify the key file path is correct and the file is readable by the bot process.
  • "Failed to upload backup": Check that the service account has Storage Object Admin permissions on the bucket.
  • Backups not appearing: Ensure the bucket name is correct and the service account has list permissions.

Character Limits Explained

Bluesky posts have a maximum length of 300 characters. Our bot reserves space for the Quote Hashtag and Word Hashtag defined in settings, so content is limited to 270 characters.

How It Works

  • Bluesky limit: 300 characters total
  • Reserved for hashtags: ~25 characters (Quote & Word hashtags from settings)
  • Safety buffer: 5 characters
  • Available for content: 270 characters

What Counts Toward the Limit

For Quotes: Quote text + Author name

For Words: Word + Definition

Color Coding

  • Green (0-240): Safe zone
  • Orange (241-270): Approaching limit
  • Red (271+): Over limit - will be truncated

Note: Content over 270 characters will be automatically truncated when saved.

Content Weighting System

The bot uses a smart weighting system to balance fresh content with seasonal relevance while avoiding overuse of the same content.

How Weighting Works

Each piece of content gets a weight that determines how likely it is to be selected:

Final Weight = Seasonal Weight ÷ (Effective Usage Count + 1)

Note: All weightings are user-configurable in settings

Usage-Based Weighting

Content penalty is based on usage rate (uses per day since added) with cooldown protection:

  • Usage rate: Total uses ÷ days since content was added
  • Dynamic cooldown: Higher usage rate = longer cooldown period
  • Cooldown calculation:
    • Base cooldown: 90 days (user configurable)
    • Usage rate scaling: 100x multiplier (user configurable)
    • Formula: 90 days × usage rate × 100
    • Example: 0.02 usage rate → 90 × 0.02 × 100 = 180 days cooldown
  • During cooldown: Content cannot be selected

Seasonal Weighting

  • No seasonal tags: 1x weight (unaffected by seasons)
  • In season - 1 matching tag: 3x weight (default)
  • In season - 2 matching tags: 4x weight (default)
  • In season - 3+ matching tags: 5x weight (default, capped)
  • Out of season: 0.3x weight penalty (default)

Examples

Example 1: New seasonal content (in season)

• Added 30 days ago, used 1 time, last used 5 days ago

• Usage rate: 1/30 = 0.033 uses/day

• Cooldown: 90 × 0.033 = 3 days (still in cooldown)

• Status: Blocked (in cooldown)

Example 2: Available seasonal content (in season)

• Added 100 days ago, used 2 times, last used 30 days ago

• Usage rate: 2/100 = 0.02 uses/day

• Cooldown: 90 × 0.02 = 1.8 days (cooldown expired)

• Weight: 3 ÷ (2 + 1) = 1.0

Example 3: Seasonal content (out of season)

• Same content as Example 2, but out of season

• Weight: (3 × 0.3) ÷ (2 + 1) = 0.3

Result: Dynamic cooldowns prevent overuse while usage rates naturally balance content selection. Seasonal content stays in season!

Event Visibility & Competition

Events compete for visibility on the map based on their location type and RSVP popularity. Only the top events in each location are shown at any given time.

How It Works

  1. Events are scored using a hybrid formula (see "Scoring Formula" below)
  2. Events compete within their location (city, county, state, or country)
  3. Only the top-scoring events up to the location's limit are visible on the map. Scores are recalculated every 5 minutes, so events can shift in and out of visibility as RSVPs change.
  4. RSVPs created before the event starts count fully; RSVPs after start count 0.5× weight

Scoring Formula

Step 1: Calculate Weighted RSVPs
Weighted RSVPs = RSVPsbefore + (RSVPsafter × 0.5)
RSVPs before event start count fully; RSVPs after start count 0.5×
Step 2: Calculate Density Score
Density = Weighted RSVPs ÷ √Duration
Using square root means longer events aren't penalized as harshly
Step 3: Calculate Final Score
Score = (Absolute Weight × Weighted RSVPs) + (Density Weight × Density)
Default weights: 30% absolute + 70% density
This balances total popularity (absolute) with engagement intensity (density)
Example:
Event A: 20 RSVPs (all before start), 4 hours
Weighted = 20, Density = 20 ÷ √4 = 10, Score = (0.3 × 20) + (0.7 × 10) = 13.0
Event B: 15 RSVPs (all before start), 1 hour
Weighted = 15, Density = 15 ÷ √1 = 15, Score = (0.3 × 15) + (0.7 × 15) = 15.0
Why square root? This approach prevents long events from dominating the map and blocking other events from visibility, while allowing popular shorter events to also show up. The balance tries to not penalize long events too much for being long while giving a variety of event lengths a fair chance. The logic will be tuned over time based on usage patterns.

Tip: To maximize visibility, encourage early RSVPs and keep your event duration reasonable. Events with high RSVP density (many RSVPs in a short time) rank higher.
